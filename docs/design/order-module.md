## 1. 订单模块

### 1.1 核心视图：看板（工作台）

#### 1.1.1 定位

- **软件默认首页**，作为用户日常工作的入口。
- 提供类似 Jira 的看板（Kanban）视图，直观展示所有进行中的订单。
- 支持拖拽操作实现阶段流转。

#### 1.1.2 绘制阶段配置

**阶段规则**：
- **系统内置阶段**：`待开始`、`完成`、`退单`。这些阶段**不可删除、不可移动位置**，固定在看板的两端。
- **自定义阶段**：位于「待开始」与「完成」之间。用户可在「设置 → 绘制阶段配置」中增、删、改、排序。每个阶段必须配置一个**专属颜色**（用于看板染色和日历视图）。

**阶段流转机制（快照技术）**：
- **当前状态（Live-Sync）**：订单表仅存储当前阶段的 `stage_id`。若用户修改了阶段名称或颜色，看板上的当前订单会**实时反映最新配置**。
- **历史记录（Append-Only）**：当订单发生阶段变更时，系统会将当时的「阶段 ID、名称、颜色」作为**快照（Snapshot）**写入流转日志。
- **删除策略**：仅当某阶段**无任何订单当前正处于此阶段**时，才允许删除。历史日志中的快照不受影响，确保了历史数据的绝对还原。

#### 1.1.3 看板列与卡片

- **列（Column）**：横向布局，每列代表一个阶段，列头显示阶段名称、颜色标识及该阶段的订单数量。
- **卡片（Card）**：纵向排列于列中，展示订单核心信息：
    - **标题**：订单编号 + 订单名称
    - **核心信息**：客户名、收款状态标签（如「已收定金」）
    - **辅助提示**：预计交付时间（显示「剩 X 天」，≤2 天标红）、稿件类别标签
    - **排序**：默认按「客户权重」降序排列（权重高的客户在上）。

#### 1.1.4 交互逻辑

- **拖拽流转**：将卡片拖入目标列（阶段），系统自动更新订单的 `current_stage` 和 `order_status`，并记录快照日志。
- **双击查看**：双击卡片打开订单详情页。
- **快速操作**：悬浮卡片时显示「编辑」、「快捷添加跟进」等按钮。
- **顶部工具栏**：提供全局筛选（如：只看紧急订单、只看今日待交）。

### 1.2 子视图：订单列表

作为看板视图的补充，提供表格化的数据浏览方式。

#### 1.2.1 列表展示字段

| # | 字段 | 数据来源 | 备注 |
|---|------|----------|------|
| 1 | 订单编号 | 自动生成 | |
| 2 | 订单名称 | 用户输入 | |
| 3 | 客户名称 | 关联客户表 | |
| 4 | 当前阶段/状态 | 枚举（7 种） | `待开始` / `线稿` / `色稿` / ... / `完成` / `退单` |
| 5 | 预计金额 | 自动求和 | = 预计定金 + 预计尾款 |
| 6 | 预计到手金额 | 自动计算 | = 预计金额 - 预计手续费 |
| 7 | 预计交付时间 | 用户输入 | |
| 8 | 订单来源 | 关联来源模板 | |
| ... | ... | ... | ... |

#### 1.2.2 搜索 & 筛选

**模糊搜索**：订单名称、订单编号、客户名称、订单内容

**下拉筛选**：
- 客户类型
- 订单来源
- 稿件类别（多选）
- 当前阶段（多选）
- 收款状态（多选）

**时间与金额筛选**：支持预计/实际时间、金额的范围查询。

### 1.3 双维度状态机

订单管理采用「工作进度 + 财务进度」双维度状态模型。

#### 1.3.1 维度一：工作进度（阶段 + 状态）

将 6 态订单状态机与看板阶段结合：

| 看板阶段 | 对应订单状态 | 描述 |
|---------|-------------|------|
| `待开始` | `未开始` | **已排期未开工**（排期强制，见 §3.0） |
| `线稿`/`色稿`/`细化`/`收尾` | `进行中` | 正在绘制 |
| `完成` | `待付尾款` | 已画完，等待客户确认/收尾款 |
| 退单 | `作废` | 订单终止 |

> **退单生命周期**：退单（拖入看板「退单」列 → `voided`）后**恒不可收款**、不可拖回流程；已收款项可在账单模块对订单「新增退款」生成出账记录。退单订单不计入客户累计消费/最大单/订单数（单独计入退单数）；订单不支持删除，在订单列表/客户详情中长期保留可查。
>
> **单向流转**：`待开始 →（自定义阶段）→ 完成` 为单向链，**开工后（离开待开始）不可返回待开始**；完成栏是最后一个流程，不能进入下一流程；退单栏只读（内容仅查看，功能可点）。

#### 1.3.2 维度二：财务进度（收款状态）

独立于工作进度，追踪资金到账情况：

| 收款状态 | 枚举值 | 含义 | 触发条件 |
|---------|--------|------|----------|
| 待付定金 | `unpaid` | 未收定金 | 新建订单默认值 |
| 已收定金 | `deposit_paid` | 定金已到账 | 填入定金支付时间 |
| 已收尾款 | `final_paid` | 尾款已到账（结清） | 填入尾款支付时间 |
| 欠款 | `arrears` | 客户长期未付 | 手动标记 |
| 免收 | `waived` | 赠单 / 免单 | 手动标记 |

### 1.4 订单详情页

#### 1.4.1 整体布局

采用「左主右辅」的双栏布局。

**左栏（主内容区）**：
1.  **顶部阶段进度条**：横向展示订单当前所处的阶段，高亮当前节点。
2.  **基本信息卡**：展示所有订单元数据。
3.  **附件管理卡**：分类 Tab（全部/参考图/草图/终稿/其他），支持拖拽上传和预览。终稿文件在订单结单后自动同步至客户画廊。
4.  **跟进记录时间线**：时间线式布局，记录插画师的工作笔记、客户反馈、系统日志（状态变更、收款记录等）。

**右栏（侧栏）**：
1.  **金额财务卡**：实时计算并展示「预计到手金额」与「实际到手金额」，提供「登记收定金/尾款」的快捷入口。
2.  **状态流转日志**：记录所有状态变更，包含阶段快照信息。
3.  **快捷操作卡**：提供「复制订单」、「跳转客户详情」等便捷功能。

> **退单订单展示**：金额财务卡不再显示收款按钮；阶段进度条提示「订单已退单，绘制流程终止」；状态流转日志保留退单前的收款/流转痕迹。

### 1.5 金额结构

```
[预计]
  预计定金 + 预计尾款 → 预计金额 → (按来源规则扣减) → 预计到手金额

[实际]
  实际定金 + 实际尾款 → 实际金额 → (按来源规则扣减) → 实际到手金额
```

|---|------|------|
| 1 | 客户 ID | 主键 |
| 2 | 客户名称 | 用户输入 |

#### 2.2.1 第一栏：基本信息

展示客户全量信息：

- 客户偏好、客户平台链接、备注

分页展示该客户的所有历史订单，字段精简为：订单 ID、订单名称、订单状态、创建日期、预计收入、实收金额。支持「查看详情」跳转。

#### 2.2.3 第三栏：客户画廊

网格布局展示该客户所有已结单订单的终稿图片 (`final` 类型)。支持点击预览大图。

### 2.3 客户权重计算

#### 2.3.1 计算公式

```
权重总分 = w1 × 单价分 + w2 × 频次分 + w3 × 时效分 + w4 × 兑现分 + w5 × 信用分
```

各因子权重可在「设置 → 权重配置」中自定义，总和需为 100%。

| 因子 | 计算方式 |
|------|----------|
| 单价分 | 最大订单单价 / 全局最大单价 × 100 |
| 频次分 | 客户订单数 / 全局最多订单数 × 100 |
| 时效分 | (总实收金额 / 总预计工时) 归一化 |
| 兑现分 | Σ实际金额 / Σ预计金额 × 100 |
| 信用分 | 按时付尾款次数 / 总结单次数 × 100 |

#### 2.3.2 计算时机

- **实时重算**：订单状态变更（特别是结单、退款）时，实时重算相关客户权重。
- **全量重算**：用户在设置中修改权重公式后，触发全量客户权重重算。

## 3. 排期模块

### 3.0 排期与流转的核心约定

排期模块是「计划」与「实际」的双轨视图，前提约定如下：

1. **排期强制**：新建订单时「预计开始日期 + 预计结束日期」为**必填**（表单校验，不填无法建单）。因此**不存在「未排期订单」**这一状态，所有活跃订单都有排期。
2. **待开始 = 已排期未开工**：看板「待开始」列（`st-pending`）中的订单即为已排期但尚未开工的订单。
3. **单向流转**：`待开始` →（自定义阶段）→ `完成` → `退单` 为单向链。**开工后（离开待开始）不可返回待开始**；完成栏是最后一个流程（不能进入下一流程）；退单栏只读。
4. **实际时间由流转记录推导**（不手动维护）：
   * **实际开工** = 订单**第一次离开 `st-pending`** 的流转时间（拖入任意自定义阶段即开工）。
   * **跳步订单**：从 `st-pending` 直接拖到 `st-done`（未经过任何绘制阶段）→ 实际开工 = 实际完工 = 进完成栏时间。
   * **实际完工** = 进入 `st-done` 的流转时间。
   * 进入完成栏时，系统**回写** `actualStartDate`（离开待开始日）与 `actualEndDate`（进完成日）。
5. **超时策略**：`expectedEndDate` 已过且订单未完成（仍在待开始/自定义阶段）→ 甘特图条带**标红 + 超期徽章**提示，**不自动修改任何排期数据**，由用户决定是否手动顺延。
6. **提前完成**：订单进完成栏早于 `expectedEndDate` → 回写实际时间，甘特图条带显示**完工标记**，计划与实际的差距可复盘。

### 3.1 核心视图：甘特图（Gantt Chart）

#### 3.1.0 数据范围

*   展示**所有活跃订单**（非 `completed`/`voided`）。由于排期强制，每个活跃订单都有 `expectedStartDate` 与 `expectedEndDate`，无需未排期区。
*   已完成/退单订单不显示（历史订单在客户详情查看）。
*   时间轴横轴范围：**以今天为中心**，`[今天 - 45 天, 今天 + 45 天]`（约 3 个月窗口），保证「今天」恒在视野中央、视野稳定，单子少时横轴也不会过短。订单超出窗口时条带部分超出，可拖动/缩放查看。

#### 3.1.1 布局与交互

*   **顶部时间轴**：横向时间刻度，支持缩放（日 / 周 / 月 / 季），可左右滑动。
*   **左侧任务栏**（固定列）：纵向列出所有活跃订单（订单编号 + 名称 + 阶段色点），与甘特区纵向同步滚动。
*   **中间甘特区**：绘制双轨条带（见 3.1.2）。
*   **工具栏**：缩放切换（日/周/月/季 segmented chips）、「今天」定位按钮、客户/阶段筛选、图例。
*   **纵向布局**：甘特区高度**撑满可用视口**（不随内容行数收缩），空白处以淡色水平网格线 + 周分隔线填充，视觉上是一张完整排期表。

#### 3.1.2 视觉元素（双轨条带）

*   **双轨条带**：每张订单条带由两层构成——
    *   **计划层（打底）**：半透明浅色，宽度 = `expectedStartDate → expectedEndDate`，表达「计划占用区间」。
    *   **实际层（实色叠加）**：订单当前阶段色（由 `currentStage` 对应阶段颜色决定），宽度 = `实际开工 → 当前/实际完工`，表达「实际进度」。
    *   **完工标记**：已进完成栏（`actualEndDate` 已回写）的条带显示完工标识（如勾号/实心端帽），实际层即实际完工为止。
*   **超期条带**：`expectedEndDate < 今天` 且订单未完成 → 条带红色边框 + 右上角「超期」红色徽章，计划层与实际层均可标红提示。
*   **内容**：条带上显示订单编号 + 订单名称。
*   **并行显示**：允许多个订单在同一时间段重叠，条带按 track 贪心分配纵向错开排列，不遮挡。
*   **拖拽编辑**：支持拖拽条带调整「预计开始/结束时间」——整条平移改开始+结束、拖边缘改持续时间；按当前缩放粒度吸附（日/周）；自动同步至订单详情/看板/客户详情。
*   **时间指示**：一条垂直红线标记当前时间（顶部带红点）。

#### 3.1.3 功能

*   **缩放切换**：日 / 周 / 月 / 季四档全保留（单子多时用月/季概览，单子少时用日/周看细节）。
*   **快速定位**：点击「今天」跳转到当前时间位置（今天恒在窗口中央）。
*   **筛选**：按客户（下拉）、阶段（多选）筛选订单。
*   **颜色图例**：显示全部阶段颜色，方便对照。

### 3.2 与其他模块的联动

*   **联动看板与订单详情**：订单的「预计时间」变更（详情/列表编辑）会实时同步到甘特图；甘特图拖拽改时间后，订单详情、看板排期同步更新。
*   **联动阶段**：订单阶段变更（如从线稿到色稿）→ 甘特图条带**实际层颜色**自动更新；离开待开始回写 `actualStartDate`，进完成栏回写 `actualStartDate + actualEndDate`。
*   **联动通知中心**：超期订单进入「紧急」类提醒（与跟进催办并列），点击跳转订单详情。

### 3.3 技术方案（DDD）

*   纯 CSS 实现（绝对定位条带 + 刻度网格），无第三方图表库。
*   拖拽用 Pointer Events（沿用看板经验，鼠标 + 触屏统一）。
*   新增 `src/domain/gantt/` 纯函数层（可单测）：
    *   `gantt-scales.ts`：缩放定义（day/week/month/quarter）、刻度生成、时间↔像素换算（pxPerMs / timeToX / xToTime）、以今天为中心的横轴范围计算（`computeRange` 改为固定窗口）。
    *   `gantt-tracks.ts`：并行订单 track 分配（按时间区间贪心，重叠订单分不同 track）。
    *   `gantt-snap.ts`：拖拽吸附（按当前缩放粒度取整）。
*   新增排期领域推导（实际时间、超期判定、完工判定，可单测）：
    *   `schedule-progress.ts`：从 `stageTransitions` 推导 `actualStartDate` / `actualEndDate`（第一次离开 st-pending / 进入 st-done）。
    *   `schedule-status.ts`：订单排期状态机（未开工 / 进行中 / 超期 / 已完工 / 提前完工），供甘特图染色、徽章、通知使用。

## 4. 跟进模块与通知中心

### 4.1 通知中心

#### 4.1.1 入口
*   **入口**：软件右上角导航栏的图标。
*   **视觉提示**：当有未读通知时，图标右上角显示**红点**或**数字角标**。
*   **交互**：点击图标弹出通知面板。

#### 4.1.2 通知类型
| 类型 | 触发条件 | 示例 |
|------|---------|------|
| **紧急催收** | 订单处于「待付定金/尾款」状态超期（天数可配置） | `[紧急] 客户 A 的订单「XX」尾款已逾期 3 天` |
| **即将到期** | 订单距离「预计交付时间」 ≤ 2 天 | `[交付] 订单「XX」距预计交付还有 2 天` |
| **每日汇总** | 每日定时推送（时间可配置） | `[日报] 今日有 3 个订单待处理...` |
| **跟进催办** | 跟进条目设置的「截止日期」到期 | `[跟进] 关于订单「XX」的修改意见今日到期` |

#### 4.1.3 通知管理
*   **已读/未读**：点击通知标记为「已读」，红点消失。
*   **跳转**：点击通知项，跳转到对应的订单或跟进详情。

### 4.2 跟进列表

#### 4.2.1 列表字段
| # | 字段 | 说明 |
|---|------|------|
| 1 | **标题** | 跟进内容的简要描述 |
| 2 | **关联对象** | 关联的订单/客户 |
| 3 | **类型** | 预置：`客户反馈` / `修改意见` / `工作备忘` / `催收记录` / `其他`（支持自定义） |
| 4 | **优先级** | `高` / `中` / `低`（视觉区分） |
| 5 | **截止日期** | 可选，到期进入通知中心 |
| 6 | **状态** | `待处理` / `已完成` |
| 7 | **创建时间** | 记录时间 |

#### 4.2.2 核心功能
1.  **快速创建**：列表顶部提供「新建跟进」按钮。
2.  **状态管理**：标记「已完成」，已完成条目可折叠。
3.  **筛选与排序**：

4.  **数据同步**：与订单详情页的「跟进记录时间线」数据同源、实时同步。

*   **跟进类型管理**：支持用户自定义跟进类型。

## 5. 收款模块

### 5.1 核心定位
轻量级的**资金流水账本**（账单化），从财务视角汇总所有收款记录。每条流水带**方向**：

| 方向 | 语义 | 产生方式 |
|------|------|----------|
| `入账`（in） | 收到客户的钱（定金/尾款） | 「新增记录」选择订单登记收款 |
| `出账`（out） | 把钱退回客户（退单退款）/ 红冲冲销 | 「新增退款」；入账红冲自动生成 |

### 5.2 顶部统计卡片（实收口径，所见即所得）
进入账单页默认限定**本月**（本月 1 号 ~ 今天），四卡数值随筛选结果实时变化：

| 卡片 | 口径 |
|------|------|
| **入账（到手）** | 筛选范围内有效入账的**到手金额**合计（扣手续费；被红冲的入账不计） |
| **出账（退款）** | 筛选范围内**手动退款**出账合计（红冲是冲销不是实出，不计） |
| **净收入** | 入账到手 − 出账（红冲对互抵为 0） |
| **待收总额** | 筛选结果涉及订单中「待收订单」（非完成/非退单）剩余应收的**到手金额**合计 |

> **红冲对**（被红冲入账 + 红冲出账）在统计中互抵为 0；账本明细仍保留两笔（审计痕迹）。

### 5.3 流水列表字段
| # | 字段 | 说明 |
|---|------|------|
| 1 | **账单号** | `RC` + 年月日 + 3 位随机数（如 RC260801001） |
| 2 | **到账时间** | 到账/退款日期时间 |
| 3 | **方向** | 入账 / 出账；被红冲的入账额外标「已红冲」 |
| 4 | **金额** | 入账正数；出账负数显示 |
| 5 | **预计** | 该笔对应的订单预计值（出账显示 —） |
| 6 | **手续费** | 按来源规则计算；出账与被红冲入账无手续费 |
| 7 | **到手金额** | 入账：金额 − 手续费；手动退款：全额实出；红冲/被红冲：— / ¥0 |
| 8 | **订单** | 订单编号 + 名称（点击跳转订单详情） |
| 9 | **客户** | 订单所属客户 |
| 10 | **类型** | 入账细分：`定金` / `尾款`；出账无类型 |
| 11 | **备注** | 可选（退款默认「退单退款」，红冲默认「红冲 原单号」） |

### 5.4 核心操作
*   **新增记录（入账）**：选择订单、类型、金额、日期。提交后自动联动更新订单的 `实际金额`、`收款状态`、`支付时间`、工作状态（收定金→未开始 / 收尾款→完成）。
    *   订单可收款前提：**未完成、未退单、未结清、未免收**（`isOrderCollectible`）。
*   **新增退款（出账）**：仅**已退单（voided）**且存在有效入账的订单可退款；金额缺省为「可退金额 = 入账合计 − 已出账合计」，不能超出。退款不改变订单收款状态（退单保持 voided）。
*   **红冲（代替删除）**：仅入账可红冲，生成一条金额相同、方向相反的出账（`refundOf` 指向被冲销单），**原账单保留**（审计原则，账单不可删除）。入账被冲销后，订单收款状态按剩余入账流水重算（完成→待付尾款、已收尾款→已收定金/待付定金），重新可收款。
*   **撤销退款**：**手动退款**出账可撤销（误录时恢复订单可退金额）；红冲生成的出账是审计凭证，**不可撤销**。
*   **编辑入账**：金额/到账日期/备注，保存后联动重算订单收款状态。

### 5.5 统计口径
*   入账、出账、净收入、待收四卡统一为**实收/实出口径**（到手金额）。
*   被红冲的入账不视为实收（已全额退回），其手续费不计损失；红冲对净额归零。
*   手动退款为真实资金流出，计入出账并冲抵净收入（手续费损失保留）。

### 5.6 筛选
*   **方向主筛选**：全部 / 入账 / 出账（账单化后方向是核心维度）。
*   **高级区**：收款类型（定金/尾款）、到账日期范围、金额范围（最低/最高）、订单、客户。
*   **全局搜索**：账单号、订单编号、订单名称、客户名、备注。
*   **默认范围**：进入页面默认本月；「重置」清空所有搜索项（含日期范围）回到全部账单。

## 6. 统计模块

### 6.1 统一时间范围筛选器
在统计模块所有页面（仪表盘、详细报表）的顶部，提供一个统一的**时间范围筛选器**。

*   **快捷选项**：`今日`、`本周`、`本月`、`本季度`、`今年`。
*   **自定义范围**：点击后弹出日期选择器，允许用户精确指定「开始日期」和「结束日期」（例如：`2026-03-02` 至 `2026-07-02`）。
*   **交互**：选择时间范围后，仪表盘的所有指标、图表及详细报表的数据**实时联动更新**。
*   **导出**：在筛选器旁提供「导出当前报表」按钮，导出筛选后的详细数据为 CSV。

### 6.2 核心视图：仪表盘（Dashboard）

作为统计模块的默认入口，以卡片和图表形式一览核心业务指标。

#### 6.2.1 核心指标卡片
*   **总收入** / **订单数**：根据当前时间范围动态计算。
*   **待收总金额**：当前时间范围内的负债总额。
*   **平均客户权重**：当前时间范围内活跃客户的平均权重。

#### 6.2.2 关键图表（随筛选器联动）
*   **收入趋势图**：折线图，X轴为时间（粒度随筛选范围自动调整，如周/月），Y轴为收入。
*   **工作量趋势图**：柱状图，展示各时间周期完成订单数。
*   **阶段耗时分布**：饼图，展示当前时间范围内，所有订单各阶段耗时占比。
*   **客户价值矩阵**：散点图，横轴为客户权重，纵轴为累计贡献金额。

### 6.3 详细报表

提供多维度的数据下钻分析，支持导出 CSV。所有报表均**继承顶部时间范围筛选器**的设置。

#### 6.3.1 时间维度报表
*   **收入明细报表**：按时间（日/周/月）汇总收入、订单数、净利润明细。
*   **工时统计报表**：分析时间范围内，各订单、各阶段的实际耗时。

#### 6.3.2 客户维度报表
*   **客户贡献榜**：按客户累计消费排序。
*   **客户欠款/免单统计**：汇总存在欠款或享受免单的客户及其订单详情。

#### 6.3.3 业务维度报表
*   **来源分析**：按订单来源统计订单量、收入、手续费支出。
*   **稿件类型分析**：按稿件类别统计订单分布。
*   **订单欠款/免单统计**：汇总所有 `arrears`/`waived` 状态的订单。

## 7. 归档模块（已于 2026-08-01 移除）

### 7.1 移除原因
经评审，归档对单兵插画师规模必要性弱，且存在设计矛盾（归档移出客户统计导致「累计消费」缩水、归档页缺失导致不可恢复）。**已整体移除** `isArchived` 字段、归档路由/导航与归档入口。

### 7.2 替代机制
*   **工作视图自动收敛**：订单列表与看板只展示**活跃订单**（非已结单/非退单）——已完成与退单订单天然离开主视图，无需手动打标。
*   **历史订单入口**：已完成/退单的历史订单统一在**客户详情 → 历史订单**中查看（展示全部订单，含状态徽章）。
*   **客户统计口径**：统计覆盖客户**全量历史订单**（累计消费/订单数/退单数等为真「累计」），不再随归档缩水。
*   **订单不可删除**：订单不支持删除（无删除入口/勾选/批量操作），作为业务档案长期保留，通过订单列表/客户详情随时可查。

## 8. 数据存储规范

- **存储模式**：纯前端方案，数据存储在浏览器本地。
