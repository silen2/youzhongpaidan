**插画师 / 画手专用的本地接单排单管理工具。** 围绕「订单 → 绘制阶段流转 → 排期 → 收款 → 统计」的完整接单流程设计，所有数据保存在浏览器本地，无需服务器、无需注册登录。

> **在线使用**：无论 PC 还是平板，浏览器打开 **https://silen2.github.io/youzhongpaidan/** 即可直接单机使用。数据存储在各自设备的浏览器中，互不共享、不上传任何服务器。

## 功能特性

- **看板式阶段流转**：订单卡片按绘制阶段（待开始/线稿/色稿/细化/收尾/完成/退单）分列，拖拽即可流转，自动记录每段耗时
- **排期甘特图**：可视化排期，拖拽调整时间，滚轮 / 双指缩放，实际进度条带一目了然
- **完整收款管理**：定金 / 尾款 / 欠款 / 免单 / 退单退款，平台手续费自动计算，账单流水可追溯
- **客户体系**：客户档案、类型、平台、联系方式，历史订单与终稿画廊，权重自动计算决定排序
- **跟进系统**：催收、反馈、修改意见、工作备忘，按到期日统一管理
- **统计分析**：收入趋势、订单分布、交付统计、客户价值、欠款/免单等报表实时计算
- **本地优先**：数据存于浏览器 IndexedDB，纯本地、可离线（PWA）、无隐私上传
- **多端自适应**：PC / 平板 / 手机响应式布局，触屏手势（拖拽、双指调行高、单击进详情）全支持
- **深度可配置**：11 套主题、自定义背景与头图、阶段/类别/来源/跟进类型均可自定义

## 快速开始

### 在线使用（零安装）

打开 **https://silen2.github.io/youzhongpaidan/** 即可使用。支持 PWA：

- **PC**：Chrome / Edge 地址栏右侧点击「安装」图标，可像桌面应用一样独立运行
- **iPad / 平板**：Safari 打开后点击分享 → 「添加到主屏幕」，全屏运行且支持**离线使用**

### 本地开发

```bash
# 安装依赖（项目使用 pnpm）
pnpm install

# 启动开发服务器（默认 http://localhost:5173/youzhongpaidan/）
pnpm dev

# 运行单元测试
pnpm test:run

# 生产构建（输出到 dist/）
pnpm build

# 本地预览生产产物
pnpm preview
```

> 说明：`vite.config.ts` 配置了 `base: '/youzhongpaidan/'`（GitHub Pages 子路径部署需要），因此本地开发地址同样带该前缀。

## 使用手册：从新建客户到订单完成

一笔订单的完整生命周期：

```
① 新建客户 ──→ ② 新建订单 ──→ ③ 排期确认 ──→ ④ 收定金
                                                    │
                    ┌───────────────────────────────┘
                    ▼
              ⑤ 看板阶段流转（线稿→色稿→细化→收尾）
                    │
                    ▼
              ⑥ 完成绘制（拖入「完成」栏 → 待收尾款）
                    │
                    ▼
              ⑦ 收尾款 → 结单（completed）
                    │
                    ▼
              ⑧ 订单完成：进入客户历史订单，终稿自动进客户画廊，计入统计
```

- 中间任何时候都可以：记录**跟进**、上传**附件**、在**甘特图**调整排期
- 特殊情况：**欠款**（先开工后收款）、**免单**、**退单**（作废）

### 第 1 步：新建客户

**位置：左侧导航 → 客户 → 右上角「+ 新建客户」**

| 字段 | 必填 | 说明 |
|---|---|---|
| 客户名称 | ✅ | 如：阿伟、米画师-XX |
| 客户类型 | — | 新客户 / 回头客 / VIP客户 / 合作方（可自定义），影响权重 |
| 平台 | ✅ | **接单来源平台**（米画师 / Pixiv / 微博 / QQ 等）。新建订单时自动关联该平台的来源模板与手续费率 |
| 平台主页链接 | — | 可粘贴主页链接方便跳转 |
| QQ / 微信 / 邮箱 / 电话 | — | 联系方式，按需填写 |
| 偏好/习惯 | — | 如：偏好半身像、常用画风、忌讳 |
| 备注 | — | 自由记录 |

> 客户创建后，其**权重**（决定看板排序）与**统计字段**由系统根据历史订单自动计算。

### 第 2 步：新建订单

**位置：工作台（看板）右上角「+ 新建订单」，或订单列表右上角「+ 新建订单」**

**基本信息**：订单名称（必填）、客户（必填，可搜索）

**接单信息**：接单来源（选择客户后自动关联，实时显示手续费与到手金额）、来源链接、用途（个人/商用）、紧急订单开关

**金额与收款**：
- 收款方式三选一：**正常收款**（定金+尾款）、**欠款**（先做后收）、**免单**（金额归零）
- **已收定金**（新建时可勾选）：勾选后定金按预计金额登记到账，订单直接进入「待开始」
- **预计金额**（必填）：输入后实时显示手续费与到手金额
- **定金金额**：按需填写；**尾款金额**：自动计算（= 预计金额 − 定金），只读

**排期**：预计交付日期（必填）、预计开始日期（必填）

**内容与备注**：订单内容/需求描述、稿件类别（多选）

**保存后**：订单出现在看板「待开始」列，收款徽章显示「未收款」。

### 第 3 步：排期确认

**位置：左侧导航 → 排期（甘特图）**

- 拖拽条带整体移动调整时间，拖拽两端手柄单独调整开始/结束日期
- 滚轮（PC）或双指捏合（平板）缩放时间密度；拖动行间分割线调整行高
- 条带下方是**实际层**：按阶段流转时间分段染色，直观看到每段实际耗时
- 超期订单显示「超期」徽章，已完工显示「✓ 已完工」

### 第 4 步：收定金（开工前提）

**位置：工作台卡片悬浮操作，或订单详情页**

- 看板卡片点击「收定金」一键入账；订单详情页可**修改实际到账金额**
- 效果：收款状态 `未收款 → 已收定金`；工作状态 `待付定金 → 未开始`；账单模块生成定金流水（含手续费）；客户统计同步更新

> 若新建订单时勾选了「已收定金」，此步可跳过。

### 第 5 步：看板阶段流转

**位置：工作台（看板）**。看板按阶段分列：**待开始 → 线稿 → 色稿 → 细化 → 收尾 → 完成 → 退单**。

- **拖拽卡片**到目标阶段列即流转（PC 鼠标 / 平板手指均可）
- 卡片**触屏单击 / 桌面双击**进入订单详情；悬浮操作提供详情 / 收款 / 跟进 / 编辑 / 隐藏
- 流转规则（系统自动约束）：阶段只能**单向推进**，开工后不能退回「待开始」；进入「完成」栏后是终点；每次流转自动记录时间

顶部筛选：**全部 / 只看紧急 / 今日待交**。

### 第 6 步：进行中的日常管理

**跟进**（催收 / 反馈 / 备忘）：看板卡片「跟进」按钮或订单详情页「+ 跟进」，类型含客户反馈/修改意见/工作备忘/催收记录等；**跟进列表**页统一管理待办，按到期日排序。

**附件**（参考图 / 草图 / 终稿）：订单详情页 → 附件管理，按类型分 Tab，支持点击上传或**拖拽图片**；终稿（final）附件在订单结单后**自动进入客户画廊**。

### 第 7 步：完成绘制 → 收尾款 → 结单

1. 把卡片拖到看板「**完成**」列：工作状态变为 `待收尾款`，实际完工日期自动回写，禁止再拖回其他阶段
2. 点击「**收尾款**」（看板卡片或订单详情页）：收款状态 `已收定金 → 已收尾款`，**订单状态 → 已完成（completed），正式结单**

结单后的变化：订单从看板/活跃列表消失（进入客户历史订单）；客户统计自动更新；**终稿自动进客户画廊**；收入计入统计分析。

### 第 8 步：订单完成后

- **客户详情 → 历史订单**：查看该客户所有已完成 / 退单订单
- **客户画廊**：已结单订单的终稿按时间展示
- **统计分析**：收入、订单、交付、客户价值、欠款/免单等报表自动更新

### 特殊场景

| 场景 | 说明 |
|---|---|
| **欠款** | 新建订单选「欠款」，订单照常流转交付，收款状态为「欠款」，后续补收；统计中欠款客户单独列出便于催收 |
| **免单** | 新建订单选「免单」，金额归零，无需收款；统计中单独计入免单金额 |
| **退单（作废）** | 订单列表 → 操作菜单 → 退单（或看板拖入「退单」列），二次确认后作废；退单后不可再收款，已收款项在**账单模块**走退款；退单订单保留在客户历史订单 |
| **紧急订单** | 新建时开启「紧急」，看板「只看紧急」一键聚焦；临期卡片自动标红 |
| **复制订单** | 订单列表操作菜单「复制」：复制名称/内容/客户/来源/金额/排期/类别，新单重置为「未开始 + 待开始 + 未收款」，适合同客户重复单 |

### 常用技巧

- 订单多了：列表支持搜索、类型筛选、高级搜索、自定义排序与列显隐
- 行高不合适：拖动行间分割线调行高；**平板双指捏合**同样可调
- 想知道收入：统计 → 收入趋势（可切换范围/粒度）
- 排期撞车：甘特图放大看重叠，拖拽错开
- 换设备使用：数据在浏览器本地，各设备独立；需要迁移用「设置 → 通知与数据」的导出/导入备份
- 离线使用：PC 安装应用 / iPad 添加到主屏幕后，断网也能用

### 核心概念速查

| 术语 | 含义 |
|---|---|
| 工作状态 | 待付定金 → 未开始 → 进行中 → 待收尾款 → 已完成 / 已退单 |
| 收款状态 | 未收款 / 已收定金 / 已收尾款 / 欠款 / 免单 |
| 阶段 | 绘制流程列：待开始 / 线稿 / 色稿 / 细化 / 收尾 / 完成 / 退单 |
| 结单 | 收尾款后订单状态变为「已完成」，一笔订单真正完成 |

## 架构设计

项目采用 **DDD（领域驱动设计）分层**，核心原则：**领域逻辑是纯函数，不依赖 DOM / IndexedDB / Vue**。

```
┌─────────────────────────────────────────────┐
│  视图层 views/  components/                 │  UI 组件：渲染、交互、ECharts 图表
│  （只编排，不含业务规则）                      │
├─────────────────────────────────────────────┤
│  状态层 stores/（Pinia）                     │  全局状态：订单/客户/账单/设置/主题/偏好
│  组合领域纯函数 + 调用 db 读写，暴露 action    │
├─────────────────────────────────────────────┤
│  领域层 domain/（纯函数，可单测）              │  核心业务规则：金额/费用/状态机/统计聚合
│  ── 不 import 任何 Vue / db / DOM            │
├─────────────────────────────────────────────┤
│  持久层 db/（Dexie）                         │  IndexedDB 表结构、初始化、统计重算
└─────────────────────────────────────────────┘
```

### 分层职责

**领域层 `src/domain/`** —— 项目的心脏。全部为纯函数（输入数据 → 输出结果），无副作用，因此可独立单测（450+ 用例主要覆盖此层）：

- `order/`：订单编号生成、状态机、收款状态流转、金额输入、手续费计算
- `statistics/`：收入、订单、交付、客户价值、欠款免单、阶段耗时等统计聚合纯函数
- `gantt/`：甘特图时间轴刻度、时间换算、排期条带
- `schedule/`：排期进度推导、排期状态（超期/完工）
- `customer/`：客户统计、权重计算、排序规则
- `payment/`：收款记录领域模型
- `shared/`：分页等通用逻辑

**状态层 `src/stores/`** —— Pinia store，组合领域纯函数与 db 读写，向视图暴露响应式状态和 action：

- `order.ts`：订单 + 附件 + 跟进 + 阶段流转
- `customer.ts`：客户 CRUD 与统计刷新
- `payment.ts`：收款流水
- `settings.ts`：阶段/来源/类别等模板配置
- `theme.ts`：主题、自定义背景/头图（localStorage 持久化）
- `preferences.ts`：用户偏好（甘特尺寸、订单编号规则等）
- `notification.ts`：通知与数据管理

**视图层 `src/views/`** —— 页面组件，按模块分目录，只负责编排 store 与组件。

### 数据流

```
视图操作 → store action → 领域纯函数（规则计算）→ Dexie 写入 IndexedDB
                      ↑                                    │
                      └──── store 响应式状态刷新 ←──────────┘
```

统计页全部报表由 `computed` 惰性求值：不在统计页时零开销，数据变更后自动重算。

## 数据库设计

IndexedDB 数据库，库名 `hetong-jira`：

| 表 | 说明 | 索引 |
|---|---|---|
| `orders` | 订单主表（含排期、金额、状态） | orderNo, customerId, orderStatus, paymentStatus, currentStage, expectedStartDate, expectedEndDate, createdAt |
| `orderCategories` | 订单-稿件类别关联 | orderId, categoryId |
| `customers` | 客户（含统计字段与权重） | name, typeId, weight, orderCount |
| `sources` | 接单来源模板（平台及手续费） | name, isEnabled |
| `categories` | 稿件类别（立绘/插画等） | name, isEnabled |
| `customerTypes` | 客户类型 | name, isEnabled |
| `stages` | 绘制阶段（系统内置 + 自定义） | name, position |
| `paymentRecords` | 收款流水（定金/尾款/退款/红冲） | orderId, type, receivedAt |
| `followUps` | 跟进事项 | orderId, customerId, status, dueDate, priority |
| `stageTransitions` | 阶段流转记录（甘特实际进度推导） | orderId, transitionDate |
| `orderAttachments` | 图片附件（原图 Blob + 缩略图 Blob） | orderId, type, uploadedAt |
| `notifications` | 通知 | type, isRead, createdAt |
| `weightConfig` | 权重公式配置 | — |
| `followUpTypes` | 跟进类型模板 | name |

附件（原图 + 320px 缩略图）以 **Blob 二进制**形式存入 IndexedDB，不落库 base64。

## 构建与部署

### GitHub Pages（当前方案）

1. 代码推送到 `main` 分支
2. GitHub Actions（`.github/workflows/deploy.yml`）自动执行：`pnpm install --frozen-lockfile` → `pnpm build` → 部署到 GitHub Pages
3. 部署地址：https://silen2.github.io/youzhongpaidan/

关键配置：

- `vite.config.ts`：`base: '/youzhongpaidan/'`（子路径部署），路由为 hash 模式，无需服务器重写
- PWA：`registerType: 'autoUpdate'`，离线缓存全部静态资源
- iOS：`apple-touch-icon.png` + `viewport-fit=cover`，保证「添加到主屏幕」正常显示图标与刘海屏适配

### 部署到其他平台

`pnpm build` 产物为纯静态文件（`dist/`），可部署到任意静态托管（Cloudflare Pages、Vercel、Nginx 等）。

## 数据与隐私

### 数据存储位置

- **数据完全本地**：所有业务数据（订单、客户、账单、跟进、附件）存储在访问者浏览器的 IndexedDB，外观设置（主题、偏好）存 localStorage，**不上传任何服务器**
- **设备间独立**：PC 与平板的浏览器数据互不共享（不同设备的存储相互隔离）
- **PWA 离线可用**：添加到主屏幕后，即使断网也能完整使用

### 备份非常重要，请务必定期导出

你的数据**只存在于浏览器里**——浏览器一清理，数据就没了。**定期导出备份（设置 → 通知与数据 → 导出 JSON）是唯一的安全网**，建议每周导出一次并存到网盘或本地磁盘。

#### 什么情况下清理什么数据会丢失

| 操作 | 订单/客户/账单等业务数据（IndexedDB） | 主题/偏好等设置（localStorage） |
|---|---|---|
| 清理「缓存的图片和文件」（仅 HTTP 缓存） | 保留 | 保留 |
| 清理「Cookie 和网站数据 / 站点数据」 | **丢失** | **丢失** |
| 卸载浏览器 / 换设备 / 重装系统 | **丢失** | **丢失** |
| iPad 上长期不使用（约 7 天未打开） | 可能被系统自动清理 | 可能被系统自动清理 |

> 关键点：浏览器「清除浏览数据」时，如果只勾选「缓存的图片和文件」，数据不受影响；**一旦勾选「Cookie 及其他站点数据 / 网站数据」，IndexedDB 和 localStorage 会一并清除**。iPad 的 Safari 还会在长期不访问时自动回收网站数据。

#### 安全建议

1. **定期导出**：设置 → 通知与数据 → 导出 JSON，文件名带日期（如 `youzhongpaidan-backup-2026-08-02.json`），存到网盘 / 本地 / 云盘
2. **关键操作前先备份**：清理浏览器数据、换设备、重装系统之前，先导出一份
3. **导入即恢复**：设置 → 通知与数据 → 导入 JSON，将覆盖现有数据并完整恢复（含图片附件），恢复后自动刷新页面
4. 附件图片会以编码形式包含在备份文件中，备份文件体积约为实际图片体积的 1.3 倍，属正常现象
